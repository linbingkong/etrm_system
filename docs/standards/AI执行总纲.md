# AI 研发规则（总纲）

本文档是项目内所有 AI 助手与开发者的执行总纲，用于说明工作入口、规则读取顺序与不可跳过的安全边界。

具体规则已拆分到 `docs/standards` 目录，本文不重复维护细则，避免多处规则漂移。

## 1. 必读规则索引

AI 助手执行任务时，必须按任务类型读取对应文档：

1. 任何代码或文档修改：先阅读 `AGENTS.md`、本文档和 `docs/standards/AI编程规则.md`。
2. 理解产品定位、业务流程、总体架构：阅读 `docs/山东电力交易辅助决策系统-PRD文档.md`。
3. 拆分业务模块、判断功能优先级、确认组件证据：阅读 `docs/山东电力交易辅助决策系统-功能清单.md`。
4. 新增或调整菜单、路由、页面入口、按钮权限：阅读 `docs/山东电力交易辅助决策系统-菜单规划.md`。
5. 前端页面、组件、状态、请求、图表、实时数据：阅读 `docs/standards/frontend-development-guidelines.md`。
6. 后端接口、Schema、服务、数据库、缓存、实时推送：阅读 `docs/standards/backend-development-guidelines.md`。

## 2. 不可跳过原则

1. 不确定就先问；信息不足时必须说明风险，不得脑补需求或假装有把握。
2. 默认最小改动，优先复用当前目录结构、业务模块、菜单路由和开发规范。
3. 菜单和权限相关任务必须先确认 `module:function` 或 `module:function:action` 编码，再写页面或接口。
4. 前端交互优化不能替代后端校验；关键业务规则必须在后端兜底。
5. 涉及电量、电价、费用、偏差率、曲线、结算、考核的逻辑必须可测试、可追溯。
6. 本项目包含中文内容，修改文件必须使用 diff/patch 方式，避免整文件重写和编码破坏。

## 3. AI 助手执行流程

1. 开始前：用 1～3 句话复述目标，读取本文件、`AGENTS.md` 和任务相关文档。
2. 分析时：先查现有目录、文档、代码和调用边界；列出关键依据，不直接改。
3. 修改前：说明改动位置、方案、风险和预期验证方式。
4. 修改中：只触碰与任务直接相关的文件；遇到已有未提交改动，不得回退用户改动。
5. 完成后：运行与变更范围匹配的检查命令，并报告结果；无法运行时说明原因和剩余风险。

## 4. 当前项目技术边界

前端边界：

- 技术栈为 Vue 3、TypeScript、Vite、Element Plus、Pinia、ECharts、AntV X6。
- 页面目录应与菜单规划一致，例如 `market-monitoring`、`trading`、`settlement`、`system-admin`。
- WebSocket/SSE 实时数据接入必须统一封装连接、重连、订阅释放和消息解析。

后端边界：

- 技术栈为 Python、FastAPI、Pydantic v2、PostgreSQL、TimescaleDB、Redis。
- 路由层只负责参数接收、权限校验、调用服务和返回结果；业务逻辑放在 service 层。
- 金额和电价最终计算优先使用 `Decimal`，避免二进制浮点误差。

## 5. 常用检查入口

当前仓库尚未落地完整前后端脚手架。命令存在后按实际项目执行，并同步更新本文档。

前端建议检查：

```bash
cd frontend && npm run build
cd frontend && npm run test
```

后端建议检查：

```bash
cd backend && pytest
cd backend && python -m py_compile app/main.py
```

文档类修改建议检查未完成占位、旧路径和乱码替换字符：

```bash
Select-String -Path docs/**/*.md -Pattern '<按需填写占位词正则>'
```

## 6. 完成前检查清单

1. 是否已阅读本任务相关的 `docs/` 文档？
2. 是否遵循了前端或后端开发规范？
3. 新增页面、菜单或按钮时，是否符合菜单规划和权限编码规则？
4. 是否避免了无关重构、大面积重写和破坏中文编码？
5. 是否覆盖关键业务场景：交易、合同、结算、策略、权限、实时数据？
6. 是否运行了可用检查命令，并如实说明未验证项？
7. 是否需要同步更新 `AGENTS.md` 或 `docs/standards/*` 规范？
